# 大肥鱼统一记忆系统设计

日期：2026-10-27
状态：已确认，进入实施

## 1. 目标

为“大肥鱼”建立一个本机统一记忆系统，使 QQ 私聊、QQ 群聊和 dsh-pet 桌宠聊天能够共享经历，同时保留类似人类的遗忘过程：

- 7 天内完整保留文字对话，作为短期记忆。
- 7 天后由大肥鱼整理，重要内容进入长期记忆，特别重要的内容写入日记。
- 长期记忆从晋升时起保留 30 天，到期后写入日记或进入回收站。
- 日记永久保存，只追加修正，不自动删除。
- 回收站保留 7 天，之后由系统物理清理。
- 模型或整理任务失败时不改变现有记忆状态，不执行删除。
- 使用当前 DSH 模型选择，不修改模型、供应商、上下文窗口或 API Key 配置。

系统必须可以在不启用抖音连接器时完整运行。抖音好友私信、刷视频兴趣和经历接入属于可选范围，不能阻塞核心交付。抖音群聊和 `dsh-douyin-scroll` 不在范围内。

## 2. 交付形态

逻辑上交付一套统一记忆系统，技术上由一个核心 DSH 插件和平台连接器组成：

1. `dsh-dafeiyu-memory` 核心插件
   - 提供统一存储、检索、整理、日记、生命周期、备份和管理接口。
   - 注册 Cordis 服务 `dafeiyuMemory`，供其他插件通过宿主上下文调用。
   - 数据保存在 `$DSH_HOME/dafeiyu-memory/`，不保存在安装目录或 `node_modules`。
2. Aurabot QQ 连接器
   - 作为 `dsh-aurabot-qq` 的用户模块安装到 `$DSH_HOME/plugins-data/aurabot/modules/`。
   - 使用公开的 `api.on('activity')`、`api.context()` 和 `api.dsh.get()` 接口。
   - 不修改 Aurabot 已安装包。
3. dsh-pet 连接器
   - 在可维护的本地源码副本中增加薄连接层，不直接编辑已安装的 `node_modules`。
   - 聊天前查询统一记忆，聊天成功后记录用户消息和回复。
   - 保留 dsh-pet 当前的人格、模型选择、气泡和最近对话体验。
4. 抖音连接器，可选
   - 只覆盖好友私信、观看兴趣和经历，不实现群聊。
   - 若 `dsh-douyin-browser-local` 缺少稳定接入点、需要大范围改写或真实流程无法可靠验证，则停止该连接器并记录原因。
   - 抖音失败不得影响核心插件、QQ 或桌宠。

核心仓库的本地开发路径为 `work/dsh-dafeiyu-memory`。安装阶段再通过 DSH Electron 管理的本地源方式接入 desktop profile。

## 3. 非目标

- 不建立云端服务、远程数据库或向量数据库。
- 不申请或使用抖音开放平台应用。
- 不实现抖音群聊。
- 不接入 `dsh-douyin-scroll`。
- 不更改现有模型配置。
- 不复制保存图片、视频或语音二进制文件。
- 不让模型直接执行 SQL、删除文件或决定物理清理时间。
- 不把 7 天内的全部对话在每一轮都发送给模型。
- 不承诺抖音连接器是核心验收条件。

## 4. 运行环境与路径

当前目标环境：

- Windows
- Node.js 24.22.1
- DeepSeek Harness 0.2.1-rc.2
- dsh-aurabot-qq 1.0.2
- dsh-douyin-browser-local 1.4.5
- dsh-pet 0.3.8

核心数据目录：

```text
$DSH_HOME/dafeiyu-memory/
  memory.sqlite
  backups/
  spool/
  reports/
```

数据库使用 Node.js 自带的 `node:sqlite`，开启 WAL、`busy_timeout` 和外键。所有写入经单进程串行队列执行。非 Cordis 资源必须使用 `ctx.effect()` 注册清理函数；定时任务优先使用宿主生命周期管理的计时器，插件卸载后不得继续运行。

## 5. 数据模型

### 5.1 `memory_events`

保存 7 天内的完整文字经历，以及等待整理或处于回收站的原始记录。

关键字段：

- `id`：内部稳定 ID。
- `source`：`qq`、`pet` 或 `douyin`。
- `source_key`：来源侧稳定消息 ID；缺失时使用受控内容指纹。
- `conversation_kind`：`private`、`group`、`pet` 或 `system`。
- `conversation_key`：平台内稳定会话键。
- `actor_key`、`actor_name`：说话人稳定标识和显示名。
- `direction`：`incoming` 或 `outgoing`。
- `content_text`：经过长度校验的文字；媒体只保存占位描述和来源引用。
- `occurred_at`：原始发生时间，统一保存 UTC 毫秒。
- `visibility`：`owner-private`、`conversation`、`group` 或 `public`。
- `state`：`active`、`review-pending` 或 `recycle`。
- `review_due_at`、`purge_due_at`：整理和物理清理时间。
- `external_key`：来源幂等键，唯一索引。

### 5.2 `memory_items`

保存由短期记录提炼出的长期记忆。

关键字段：

- `kind`：`fact`、`preference`、`relationship`、`experience` 或 `behavior-note`。
- `subject_key`、`subject_name`：记忆涉及的人物或群聊。
- `content`：一条自足、可检索的事实。
- `importance`、`confidence`：受限范围内的数值。
- `visibility`：沿用最严格的来源可见性，不因整理而扩大。
- `promoted_at`：进入长期记忆的时间。
- `expires_at`：`promoted_at + 30 天`，不因召回自动续期。
- `state`：`active` 或 `recycle`。
- `source_refs_json`：引用原始事件或其他记忆的稳定 ID。
- `supersedes_id`：修正旧记忆时指向被替代项。

### 5.3 `diary_entries`

保存永久日记：

- `title`、`body`、`written_at`。
- `visibility` 和来源引用。
- `supersedes_id` 可表达修正，但旧日记不覆盖、不自动删除。
- 日记只保存提炼后的文字，不保存媒体二进制。

### 5.4 控制表

- `review_jobs`：7 天整理和 30 天到期整理任务，含状态、重试次数和错误代码。
- `import_ledger`：记录来源、指纹、导入时间和结果，保证重复导入幂等。
- `purge_ledger`：保留最小删除凭据，防止连接器重新导入已明确清理的数据；不保留原文。
- `schema_meta`：数据库版本和迁移状态。

## 6. 记忆生命周期

### 6.1 短期记忆

消息成功进入平台处理链后即写入 `memory_events`。收到消息和发出回复使用各自的 `source_key`，重复事件不重复写入。

从 `occurred_at` 起满 7 天后创建整理任务。系统按会话和时间分批，每批大小有上限，调用当前 DSH 模型生成结构化决定：

```json
{
  "retain": [{ "sourceIds": ["..."], "kind": "fact", "content": "...", "importance": 0.6 }],
  "diary": [{ "sourceIds": ["..."], "title": "...", "body": "..." }],
  "discard": ["..."]
}
```

输出必须通过 JSON 结构、来源 ID、长度、数量和可见性校验。模型不能引用批次外 ID，不能扩大可见范围。校验通过后在一个事务内：

1. 写入长期记忆和日记。
2. 将本批原始事件移入回收站。
3. 设置 `purge_due_at = 当前时间 + 7 天`。
4. 将整理任务标记完成。

模型超时、无文本、JSON 错误、来源不完整或数据库错误时，事务不提交，原事件继续保留并稍后重试。

### 6.2 长期记忆

长期记忆从 `promoted_at` 起保留完整 30 天。被再次聊到只增加召回统计，不刷新到期时间。重复发生的新事实形成新记忆或修正关系，不能静默延长旧项。

到期时创建最后整理任务。模型只能在以下结果中选择：

- 写入永久日记，然后将长期记忆移入回收站。
- 直接移入回收站。

失败时保持长期记忆有效，等待重试。

### 6.3 日记

日记永久保存且参与相关性检索。系统不自动删除日记，也不因磁盘压力删除日记。发生事实变化时追加修正日记，并用引用关系标记旧内容已经变化。

### 6.4 回收站与物理清理

回收站保留 7 天，期间可从管理接口恢复。到期后由确定性清理任务删除正文和索引，并在 `purge_ledger` 中留下无正文幂等标记。模型不参与具体删除时间，也不能绕过回收站。

SQLite 清理后执行 WAL checkpoint，并按空闲页比例执行增量空间回收；不在每次删除后执行完整 `VACUUM`。

## 7. 检索与上下文

“全部记忆共享”表示所有允许的内容进入同一存储并可按需检索，不表示每轮向模型传入全部记录。

默认每轮最多注入：

- 7 天短期记忆相关片段 8 条。
- 30 天长期记忆 6 条。
- 永久日记摘要 3 条。

当前平台自身的最近对话仍由原插件管理。统一记忆只提供跨会话、跨平台补充上下文。

排序考虑：

1. 当前说话人和当前会话精确匹配。
2. 文字相关度。
3. 重要程度。
4. 新近程度。
5. 曾被召回的不同日期数。

中文使用 Aurabot 已验证的二元字组思路，英文和数字按词检索；核心实现不依赖外部向量服务。索引只覆盖有效短期、长期和日记内容，不覆盖回收站。

当用户明确询问时间、平台或群聊时，查询可以收窄范围并在同一总量限制内提高精确匹配权重。

## 8. 隐私与公开投影

主人 QQ 私聊和 dsh-pet 桌宠聊天可以检索全部允许的统一记忆。其他 QQ 私聊只能获得该联系人自己的会话记忆和公开记忆，不得读取主人或其他联系人的私聊内容。QQ 群聊只能获得：

- 当前群自己的短期记录。
- 当前群可见的长期记忆。
- 明确标为公开的日记摘要。
- 不包含事实正文的通用行为限制，例如“不讨论主人的私人安排”。

核心服务不得把其他私聊原文、账号、私密身份或私密日记正文返回给 QQ 群连接器。连接器也不得自行读取数据库绕过服务投影。

抖音没有群聊范围。若实现好友私信连接器，其私信仍按私聊可见性处理，不自动扩大到其他联系人。

日志和管理状态不得记录对话正文、账号凭据或完整来源对象。

## 9. 现有数据导入

首次启用执行全量、只读、可重复的导入：

| 来源 | 目标 | 规则 |
|---|---|---|
| Aurabot `chatlog/*.jsonl` 最近 7 天 | 短期记忆 | 保留原时间、群聊或私聊来源 |
| Aurabot 较旧聊天流水 | 首次整理队列 | 不直接删除，分批整理 |
| Aurabot `memories.json` | 长期记忆 | 从导入时间起获得完整 30 天 |
| Aurabot `diary.json` | 永久日记 | 不自动删除 |
| 抖音 `shared.sqlite` | 长期记忆 | 保留来源和原有可见性，抖音可选失败不阻塞 |
| 抖音可核实的现存私信上下文 | 短期记忆 | 按原始时间计算 7 天 |
| dsh-pet `memory.json` | 短期记忆或首次整理队列 | 文件不存在时正常跳过 |

导入前为三个现有数据目录创建一致备份。导入器不修改、不清空原文件。每条导入记录使用来源稳定 ID或受控指纹写入 `import_ledger`；重复运行不得重复生成记忆。

导入失败回滚本批事务并生成不含正文的报告。核心 QQ 和桌宠导入成功后即可启用系统；抖音导入失败只记录为可选项未完成。

## 10. 连接器行为

### 10.1 QQ

- `message` 事件记录许可范围内的每条入站私聊和群聊文字，即使该群消息最终没有触发回复也要进入 7 天短期记忆；处理函数只旁听并返回未接管。
- `activity` 事件记录最终发出的出站文字。入站事件若同时出现在两个事件中，依靠来源消息 ID 去重。
- `api.context()` 在每轮前调用核心检索服务。
- 群聊请求必须显式传递群聊会话键，核心服务据此生成公开投影。
- 核心服务不可用时，Aurabot 按原有逻辑继续聊天，连接器记录去敏告警并把待写事件放入有界本地 spool。

### 10.2 dsh-pet

- 保持 `chatMemoryRounds` 当前语义，不把它改成统一库容量。
- 在调用模型前取得统一记忆上下文，与现有最近 N 轮共同构成请求。
- 只在聊天成功后记录 assistant 回复；失败请求不伪造回复。
- 核心服务不可用时继续使用原 `memory.json` 聊天路径。

### 10.3 抖音，可选

- 好友私信生成前读取统一记忆，成功发送并回读确认后记录回复。
- 视频观看的结构化兴趣和经历可写入长期候选，不复制媒体。
- 不实现群聊。
- 出现稳定接入点缺失、大范围侵入、真实浏览器目标无法验证或发送结果不确定时停止实现，不降低其他组件完成状态。

## 11. 调度、离线与并发

- DSH 运行时由核心插件定时扫描到期任务。
- 关机或插件停用期间不运行任务；下次启动按 `due_at` 补处理。
- 同一整理任务使用租约和唯一键，热重载或重复启动不得并发执行两次。
- 到期扫描、导入和连接器写入共用串行写队列；读请求可以并发。
- 插件卸载时停止新任务，等待当前短事务结束，关闭数据库并清理计时器。
- 不在一个数据库事务内调用模型；先读取批次，模型返回并校验后再开启短写事务，并再次核对来源版本。

## 12. 磁盘与备份

- 默认软上限 1 GiB，可配置但不能低于一个安全最小值。
- 达到 80% 时优先清理已经到期的回收站、执行 checkpoint 和删除超过保留期的旧备份。
- 达到上限仍不能恢复空间时进入降级状态并明确告警，不得提前删除 7 天短期记忆、有效长期记忆或日记。
- spool 有独立小上限，满后停止接收新的离线副本并告警，不覆盖旧项。
- 备份采用滚动保留并受独立总容量上限控制；迁移前备份至少保留到用户确认迁移结果。
- 附件只保存占位文字和稳定引用，不复制二进制内容。

## 13. 管理界面与可观察性

核心插件提供一个 DSH 设置页，至少包含：

- 短期、长期、日记和回收站数量。
- 下次整理时间、待处理和失败任务数量。
- 当前数据库、备份和 spool 占用。
- 按关键字搜索有效记忆。
- 查看来源类别和时间，不默认展示账号标识。
- 从回收站恢复。
- 手动将长期记忆写入日记。
- 手动永久删除回收站条目，必须二次确认。
- 手动触发备份和整理。
- 连接器状态，抖音明确标记为可选。

公开状态接口只返回计数、状态码和时间，不返回记忆正文或内部路径。

## 14. 故障语义

- 数据库打不开：核心插件进入不可用状态，不创建新空库覆盖原文件；QQ 和桌宠按原逻辑继续聊天。
- 模型整理失败：不更改记忆状态，不删除，按退避策略重试。
- 部分批次失败：已经提交的批次保持，失败批次独立重试。
- 备份失败：禁止执行即将产生物理删除的清理任务，但允许正常读取和新增短期记录。
- 达到磁盘上限：不提前删除受保护内容；停止非必要导入或 spool 增长并告警。
- 连接器重复投递：由 `external_key` 幂等拒绝，不产生重复记忆。
- 插件热重载：计时器、数据库句柄和监听器全部通过公开生命周期 disposer 清理。
- 抖音失败：仅停用抖音连接器，核心完成状态不受影响。

## 15. 验证与验收

### 15.1 自动测试

- 数据库迁移、约束、并发写入和幂等测试。
- 7 天短期到期、30 天长期到期、7 天回收站清理的边界时间测试。
- 整理成功、超时、无效 JSON、越界来源、事务失败和重试测试。
- 日记永久性和追加修正测试。
- QQ 私聊、QQ 群聊公开投影和跨会话召回测试。
- dsh-pet 最近轮数与统一记忆同时存在的测试。
- 全量导入、重复导入、缺失文件、损坏文件和回滚测试。
- 磁盘软上限、备份失败、spool 上限和启动补处理测试。
- 热重载和 disposer 清理测试。
- 抖音连接器测试单独分组，不影响核心测试结果。

自动测试只使用本地合成消息和临时数据库，不向真实 QQ 或抖音发送内容。

### 15.2 核心验收

1. QQ 群中的重要事实经整理后，可在主人 QQ 私聊中被相关问题召回。
2. QQ 私聊内容不会作为正文出现在其他 QQ 群的记忆上下文中。
3. dsh-pet 可以召回 QQ 中的允许记忆，并把新聊天写回统一库。
4. 7 天前原始记录经过成功整理后进入回收站，回收站满 7 天后物理删除。
5. 长期记忆从晋升时起保留 30 天，不因召回续期。
6. 日记在所有自动清理后仍存在。
7. 模型、备份或数据库故障不会导致默认删除。
8. 重复导入不会增加重复记录，原始数据文件保持不变。
9. 插件热重载和 DSH 重启后任务可恢复且不重复执行。
10. 不安装抖音连接器时，以上验收全部成立。

## 16. 实施顺序

1. 核心数据库、服务接口和生命周期。
2. 检索、隐私投影和管理状态。
3. 7 天、30 天、日记和回收站任务。
4. Aurabot 用户模块连接器。
5. dsh-pet 本地源码连接器。
6. 现有数据备份与全量导入。
7. 管理界面和端到端核心验收。
8. 在核心稳定后评估抖音好友私信、兴趣和经历连接器；遇到阻塞可终止该步骤。
